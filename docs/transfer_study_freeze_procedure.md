# 合成→実データ移転研究：事前登録の凍結手順

**Issue：** #211（事前登録）。親 #210。対象文書は [transfer_study_preregistration.md](transfer_study_preregistration.md)。
**この文書の状態：** 手順の案。まだ一度も凍結していない。

## 凍結とは何か

凍結は「実データを1件も見ていない時点で、解析の決め事をこの内容に固定した」という記録です。凍結した後に結果を見て決め事を変えると、それは事前登録ではなくなります。

凍結の判断と記録は人が行います。コード（`sentra/backend/research_engine/transfer/preregistration.py`）がするのは次の3つだけです。

1. 未決定の項目が残っていないかを数える（残っていれば凍結を拒否する）
2. 凍結記録に書く文書hashを計算する
3. 凍結記録の hash が今の本文と一致するかを確かめる

コードは決定内容も凍結記録も書きません。

## 凍結できる条件

次のすべてを満たしたときだけ、`prereg-status` が `"frozen": true` を返します。

| 条件 | 確かめる場所 |
|---|---|
| P1〜P14 のすべての行がある（行を消しても決定にはならない） | 未決定表 |
| すべての行の「状態」が `決定済み` か `確認済み` | 未決定表 |
| その行の「決定内容」「決定日（YYYY-MM-DD）」「決定者」が埋まっている | 未決定表 |
| 凍結記録の行に「版」「日付」「commit」「文書hash」「承認者」「レビュー者」がある | 凍結記録 |
| 凍結記録の「文書hash」が今の本文の hash と一致する | `prereg-hash` |

空欄・`—`・`未記入` は「埋まっていない」と読みます。

## 手順

作業する人は、研究責任者（または研究責任者が指名した人）です。各ステップを飛ばさないでください。

1. **決める。** 未決定表の各行について、owner・研究責任者が決定内容を決め、その行の「状態」「決定内容」「決定日」「決定者」を決定者本人が書く。
2. **確かめる。** `sentra/backend` で次を実行し、`blockers` が空であることを確かめる。

   ```bash
   python -m research_engine.transfer.cli prereg-status
   ```

   未決定が残っている間は終了コード1で、何が残っているかを全部表示します。
3. **レビューを受ける。** 決定を書いた版をレビュー者が読む。指摘があれば 1 に戻る。
4. **commit する。** 決定を書いた本文を commit する。この commit が「凍結した内容」です。
5. **hash を取る。** 同じ本文で次を実行する。

   ```bash
   python -m research_engine.transfer.cli prereg-hash
   ```

   この hash は「凍結記録」節の中身を除いて計算します。凍結記録を書き足しても値は変わりません。
6. **記録する。** 凍結記録の表に1行を足す。「版」「日付」「commit（手順4の hash）」「文書hash（手順5の値）」「承認者」「レビュー者」を、承認者本人が書く。
7. **もう一度確かめる。** `prereg-status` が `"frozen": true` と終了コード0を返すことを確かめ、凍結記録の行を commit する。
8. **ここまでが実データを開く前。** 実データの採点コードは、凍結されていない事前登録では動かない（`require_frozen`）。

合成上の順位の封印（#215）は凍結の後に行います。封印の記録は凍結した事前登録の hash を含み、凍結前に作った封印は「候補（確証解析には使えない）」として扱われます。

## 凍結の後に本文を変えたいとき

凍結後に本文を1文字でも変えると、hash が一致しなくなり、`prereg-status` は凍結されていないと返します。これは意図した動きです。

- 変更が必要なら、改訂表に「何を・なぜ・実データを見る前か後か」を書き、手順 2〜7 をやり直して**新しい版**の凍結記録を足す。前の版の行は消さない。
- 実データを見た後の変更は事前登録の変更ではなく、事後の変更として報告に分けて書く。

## この仕組みが保証しないこと

- hash は内容が同じことを確かめるだけで、誰が書いたかは保証しません。ファイルを書き換えられる人は、記録の行も書き換えられます。記録の意味を支えるのは、git の履歴とレビューです。
- 「実データを見る前に凍結した」ことは、コードでは確かめられません。凍結 commit の日時と、実データの最初の export の記録（`research_exports`）を人が突き合わせて確かめます。
- 承認者が本当にその人であることは、[docs/pilot/approvals.md](pilot/approvals.md) と同じく本人の署名・記録で確かめます。代理入力を本人の承認としません。
