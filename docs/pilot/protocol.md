# 研究protocol: 50名×21日の基礎データ収集

> 版 `pilot-protocol-v1` / 草案 / 承認前
> 承認欄は [approvals.md](approvals.md)。承認されるまで `pilot_studies.status` を `recruiting` にしない。

## 1. 目的

高校生の日々の記録と固定自己評定を、**介入を加えない条件で**収集し、時系列モデルの評価に足る基礎データを作る。

この研究で**主張しないこと**を先に書く。

- 参加者個人の状態を推定・判定しない。
- AIによる助言・応答を参加者に返さない（収集専用モード）。
- 臨床的な有効性を検証しない。
- 教員・保護者に個人の分析結果を渡さない。

この段階の成果は「データが取れること」と「測定が安定していること」であって、モデルが当たることではない。

## 2. 対象

| 項目 | 内容 |
| --- | --- |
| 対象 | 協力校に在籍する高校生 |
| 目標人数 | 50名 |
| 募集方法 | 招待コードのみ。公開signupからは参加できない |
| 年齢 | 18歳未満を含む。18歳未満は本人assent + 保護者確認の両方が必要 |

**除外条件**

- 本人が参加を希望しない場合（希望しないこと自体を記録・共有しない）
- 保護者が確認しない場合（18歳未満）
- 学校側が、現在の状況から参加が負担になると判断した生徒
- `DECISION REQUIRED`: 現に医療・相談機関の支援を受けている生徒を除外するか、含めるか。除外は「支援を受けている」という情報を研究側に発生させるため、除外自体に慎重さが要る。**決定者: 研究倫理責任者と学校責任者**

## 3. 期間

```
Day 0        登録・説明・同意
Day 1-14     baseline 期間（14日）
Day 15-21    観察期間（7日）
Day 22-      収集終了。以後の書き込みなし
```

14日+7日に分けるのは解析上の都合であり、**7日で個人の因果構造を検証できるという主張ではない**。7日でできるのは短期予測の粗い確認までである（[R1](../../sentra/docs/world-model/research-r1-real-observations.md) §3.3）。

baselineと観察で参加者が受ける画面・項目は**同じ**にする。途中で提示を変えると、変化がモデルの発見なのか提示の変更なのか分からなくなる。

## 4. 収集する項目

正本は [data-dictionary.json](data-dictionary.json)。ここでは方針だけを書く。

### 4.1 日次の固定自己評定

**毎日、同じ項目を、同じ順番で、同じ尺度で聞く。** 日によって変えない。

| # | 項目 | 尺度 | 必須 |
| --- | --- | --- | --- |
| 1 | 今日の気分 | 0〜10（0=とても悪い、10=とても良い） | 任意 |
| 2 | 今日のストレス | 0〜10（0=まったくない、10=とても強い） | 任意 |
| 3 | 昨夜の睡眠の質 | 0〜10（0=とても悪い、10=とても良い） | 任意 |
| 4 | 睡眠時間 | 時間（0.5刻み） | 任意 |
| 5 | 今日の出来事の大きさ | 0〜10（0=なにもなかった、10=とても大きい） | 任意 |

**全項目が任意である。** 答えなかったことは「欠測」として記録し、0や中央値で埋めない。埋めた瞬間、「書かなかった日」と「まん中だった日」が区別できなくなる。

- 提示順は上の1〜5で固定する。ランダム化しない（順序効果を一定にするため）。
- 尺度の文言は [consent-pack.md](consent-pack.md) の説明文と一致させる。
- `DECISION REQUIRED`: 項目6として「誰かに相談できたか」を入れるか。支援資源への接触は重要な変数だが、質問すること自体が相談を促す介入になりうる。**決定者: 研究倫理責任者**

### 4.2 自由記述

その日の記録を自由記述で1件。文字数の下限を設けない。

- 書かない日があってよい。書かなかったことを督促しない（`DECISION REQUIRED`: リマインダー通知を出すか、出すなら1日1回までか。**決定者: 研究責任者と学校責任者**）。
- 自由記述は**外部AIへ送らない**（§6）。

### 4.3 記録の過程

入力にかかった時間、書き止まり、書き直し、回答順は、既存のtelemetryとして記録する。これは分析の根拠を後から確認するためで、参加者の画面には返さない。

### 4.4 危機的記述への対応

自由記述に自傷・他害・急迫した危険の記述があった場合の扱いは [incident-runbook.md](incident-runbook.md) §3。**自動判定でモデルが診断的な表示を返すことはしない。** 収集専用モードでは外部AIへ送らないため、判定は運用側の目視レビューで行う。

- レビューの頻度: `DECISION REQUIRED`（当日中／翌営業日／リアルタイム）。**決定者: 学校責任者と研究責任者。** 「リアルタイム」と書くなら、その体制が実在することを示す必要がある。
- 参加者には、説明文の時点で「危険と思われる記述は運営者が読む場合がある」ことを明記する。読む可能性を伏せたまま読むことはしない。

## 5. 欠測と中止

### 5.1 欠測の許容

- 欠測日があっても参加を続けられる。
- 解析上の最低条件: baseline期間に**7日以上**の提出。これを下回る参加者は、時系列解析の対象から外す（データは削除しない。除外した事実と理由を記録する）。
- 欠測は理由を尋ねない。理由を尋ねると、それ自体が督促になる。

### 5.2 参加の中止

| 中止の種類 | 誰が | 結果 |
| --- | --- | --- |
| 本人の撤回 | 参加者本人。いつでも、理由不要 | 撤回時点以降の研究書き込みを止める。既収集データの扱いは本人が選ぶ（残す／削除する） |
| 保護者による撤回 | 保護者 | 同上 |
| 研究側の中止 | 研究責任者 | 事故・障害・体制不備。全参加者へ通知 |
| 学校側の中止 | 学校責任者 | 同上 |

撤回は不利益をもたらさない。成績・評価・進路に一切関係しないことを説明文に明記する（[consent-pack.md](consent-pack.md)）。

**撤回後にexportへ含めない。** 撤回時刻以降の書き込みが0であることは、dry run（[#168](https://github.com/jbjgjf/BLESC/issues/168)）の合格条件に入っている。

## 6. 収集専用モード

この研究期間中、参加者の本文と自己評定を**外部のAI APIへ送らない**。

- 停止するもの: 抽出、埋め込み、チャット応答、音声文字起こし、adaptive follow-up、参加者向けのグラフ、教員向けの推論。
- 実装: `sentra/frontend/src/lib/server/collectionMode.ts`。5つの送信点すべてがこのモジュールを参照し、参照しない新しい送信点が増えるとテストが落ちる。
- 理由は3つ。(1) AIの読み取りを返すと、参加者の書き方が変わる（測っている対象が変わる）。(2) 同意した内容が「収集」であって「第三者への送信」ではない。(3) 抽出モデルが期中に更新されると1週目と3週目が比較できなくなる。

**二次利用・fine-tuningは別のopt-in。** 本文提出への同意は、学習利用への同意ではない。既定はoffで、同意画面で個別に選ぶ。選ばなかった参加者のデータを学習に使わない。

## 7. 解析計画

### 7.1 主要な記述

- 提出率、欠測パターン、脱落率
- 自己評定の分布と、日内・曜日の変動
- 自己評定の測定安定性（[R1](../../sentra/docs/world-model/research-r1-real-observations.md) §4.2）

### 7.2 モデル

事前登録した仮説に限る（[R1](../../sentra/docs/world-model/research-r1-real-observations.md) §6）。要点だけ再掲する。

- 主要評価: heldout参加者での1日先予測のMAE。参加者単位で平均し、参加者bootstrapで区間を出す。
- 比較対象: 持続値・訓練平均・線形AR。これらに勝てない場合は、勝てなかった結果を保存する。
- 参加者を跨ぐ汎化と、既知参加者の未来予測は**別のレポート**にする。平均しない。
- 中間解析はしない。データ収集の途中で指標・分割を変えない。

### 7.3 個人への還元

この研究では、モデルの推定結果を参加者・保護者・教員へ返さない。返すのは、研究終了後の**全体の結果の要約**のみとする。

## 8. データの取り扱い

| 領域 | 含むもの | 研究exportに含めるか |
| --- | --- | --- |
| 認証 | email、login user id | 含めない |
| 対応表 | user id ↔ participant id ↔ research code | 限定管理者のみ。exportに含めない |
| 研究dataset | research code、相対日、自己評定、本文参照、provenance | 仮名化して含める |
| 運用monitor | 提出成功・欠測・失敗・撤回・purge状態 | 本文を表示しない |

- 本文の保持は暗号化列（`entries.raw_text_ciphertext`）でのみ行い、鍵は `RESEARCH_RAW_TEXT_KEY`。鍵なしでは保持そのものを行わない（平文では保持しない）。
- 保持期間と削除: `DECISION REQUIRED`（研究終了後の保持年数、削除の方法と証跡）。**決定者: データ管理責任者と研究倫理責任者**
- 本文と認証IDを、アプリログ・analytics・エラーレポートで同居させない。
