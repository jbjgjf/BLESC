# 1日検証の計画（学校を運営主体としない場合）

2026-09-19 ownerの質問に対する実施計画。これは[実時間3日dry run](dry-run/README.md)の代替合格記録ではない。対象が成人のみか未成年を含むか、募集に学校が関与するかが確定した後、対象経路を固定する。テストには成人スタッフのアカウントと合成本文だけを使う。

## 署名

採用した方針へのownerの承諾は[決定記録](decisions-2026-09-19.md)に記録済み。署名は以下の2段階を分ける。

1. **文書承認**: 研究責任者・田雨竜、データ管理責任者・王謙蘊、運用責任者・梅澤透真を署名候補とする（2026-09-19 owner指定）。各人が氏名・役割・日付・承認したprotocol版と同意文書版・記録方法を[approvals.md](approvals.md)へ自身で記録する。ownerによる候補指定は本人の受諾や署名を意味しない。存在しない学校責任者や倫理審査委員会の署名を作らない。
2. **運用判定**: 実際に演習した研究・データ管理・運用の担当が、証跡と未解決事項を読んで[演習記録](dry-run/evidence-template.md)のGo/No-Goを自身で記録する。文書の承認だけで演習合格としない。

学校が運営しないなら、学校責任者の承認欄を機械的に使用しない。募集に学校が一切関与しない場合は募集・保護者確認・危機連絡を改訂し、学校欄を適切な実担当へ変更する。未成年を含む場合の保護者の別経路確認と急迫時の連絡経路を確定するまで署名しない。倫理審査の要否は研究目的・主体・募集方法が確定してから判断し、自己判断で「承認済み」と書かない。

## 現行v1と採用方針の差分

| 項目 | 現行の確認先 | 残る整合 |
| --- | --- | --- |
| 版 | `src/lib/consent.ts`、DB migration、dry-run seedは同意文書v1。DBのstudy既定もprotocol v1 | 採用したv2本文・画面・DB値・seed・監査記録を一組で揃える。既存v1同意履歴は書き換えない。 |
| 募集・保護者 | `/pilot/join`、`/pilot/guardian`、`guardianVerification.ts`、`guardianStore.ts` は学校を配布者・確認者とする | 学校の役割を削り、未成年を含むなら保護者に直接届く独立経路と代理権確認を実装・検証する。72時間・一回限りのtoken処理は既存実装を検証する。 |
| 同意範囲 | `consent-pack.md` v2、`legalDocuments.ts`、実際の保護者画面 | 本人と保護者の項目別選択、将来のモデル学習opt-inの扱い、画面に出る文言を一つの方針に揃える。現行保護者画面は一括回答。 |
| 危機連絡 | `incident-runbook.md` は学校へ連絡する設計 | 学校を使わない場合の主担当・代替・本人または保護者への連絡判断・緊急通報への引継ぎを定義して演習する。固定レビュー時刻や応答期限は設けない案。 |
| 保持・削除 | 原文90日期限計算とpurge APIはコードに存在 | 実環境のcron設定、対象データの期限削除、失敗監視、バックアップ復元時の再削除、研究データと対応表の1年/90日削除を確認する。 |
| 結果共有・問い合わせ | v2文書と `legalDocuments.ts` の公開草案 | 実際の公開URL・予定時期・メール担当と代替・到達を確認し、配布画面に反映する。 |

## 1日で行う順序

| 時間の目安 | 作業 | 残す証跡 |
| --- | --- | --- |
| 0–1時間 | 対象年齢・募集経路・責任者を固定し、deployment SHA・DB ref・文書版を記録 | 担当者と範囲、設定の記録 |
| 1–3時間 | 10テストアカウントで招待、本人同意、保護者の別経路確認、拒否、期限切れ、二重利用を通す | 画面記録、DBの状態、失敗理由 |
| 3–5時間 | 合成本文・自己評定の提出、失敗と再送、撤回後書込拒否、他人のデータへのアクセス拒否、exportのPIIを確認 | 照合SQL結果、外部通信記録 |
| 5–7時間 | 削除、期限切れ原文のpurge、バックアップ復元と再削除、鍵のローテーションを隔離環境で試す | 件数・時刻・担当者・復旧結果。秘密値と本文は貼らない |
| 7–8時間 | 合成の危機記述を使い、担当・代替・連絡先への引継ぎを通す | 覚知、判断、連絡、完了の時刻と担当。合格条件を定時監視や30分応答とはしない |
| 最後 | 全証跡を照合し、未確認項目を空欄にせず列挙する | 1日検証のGo/No-Go。実時間3日試験の合格とは書かない |

日付境界、翌日への持ち越し、欠測、連続提出、担当交代は時計を進める単体・結合テストで**機能の予備検証**ができる。実際の時間経過と引継ぎの運用は同じ日に完了したとは言えない。募集開始条件を1日版へ変更するなら、研究責任者が何のリスクを受容するかと理由を明記した別の計画変更が必要であり、技術テスト結果だけで置き換えない。
