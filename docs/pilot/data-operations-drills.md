# 削除・撤回・危機的開示の演習記録テンプレート（#167）

dry run（#168）の day 3 と、本調査開始前に1回、この3つを**実際に手を動かして**通す。
読み合わせは演習ではない。手順書が正しいかどうかは、手順書を読んでも分からない。

記録は1演習1ファイル。dry runでは #168 のevidenceに添付する。

各演習に共通する条件:

- 実在の高校生のデータを使わない。訓練された成人スタッフの合成本文だけを使う。
- 所要時間を測る。「できた」ではなく「何分かかったか」が、本番で判断材料になる。
- 手順書どおりに動かなかった点は、成功扱いにせずIssueにする。

## 演習C: 危機的記述の開示（tabletop）

想定: 提出された本文に、緊急の危険を示す記述があった。

**この演習だけは、実際に外部へ連絡しない。** 連絡先・宛先・文面の到達までを机上で確認
し、送信はしない。誤送信そのものが事故になる。

| 項目 | 記入 |
| --- | --- |
| 実施日時 / 参加者（役割ごと） |  |
| 想定シナリオ |  |

1. 検知: `safety_assessment` の `risk_level = crisis` がどこに出るか、誰が最初に見るか。
   - 検知から人が気づくまでの想定時間: ___ 分
   - 夜間・休日の場合の想定時間: ___ 分
2. 特定: `research_code` → 実アカウント → 学校側の担当者。
   - 使う経路: identity map（`RESEARCH_IDENTITY_MAP_USER_IDS`）
   - この経路を使える人が今何人いるか: ___ 人
   - **その全員が連絡不能な時間帯があるか**: □ ある（___時〜___時） / □ ない
3. 連絡: 誰から誰へ、どの順で。文面の版: ___
4. 記録: 開示した事実・範囲・理由をどこに残すか: ___
5. 参加者本人への事後説明: いつ・誰が・何を伝えるか: ___

判定と持ち帰り:

- 手順のうち、実行できないと分かった箇所: ___
- 2 で「連絡不能な時間帯がある」に該当した場合、それは **No-Go 事由** として #168 に
  記録する。危険な記述に気づける仕組みがあっても、気づいた人が誰にも繋げない時間帯が
  あるなら、その時間帯に収集してはいけない。
