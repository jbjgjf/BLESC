# 学校導入のリスクモデル（草案・未レビュー）

2026-10-11 作成。対象コミット `origin/main` 2fadb92。AI の支援で起草した。**研究責任者と臨床協力者のレビュー前であり、承認されたリスク評価ではない。**

#7（3か月ロードマップ）を閉じたとき、10項目のうち「School deployment risk model」だけが「リポジトリ内に該当するものが見つからない」とされた。この文書はその穴を埋める最初の版である。

## 1. 目的と範囲

学校に導入したときに起きうる害を、**いま何がそれを抑えていて、何が抑えていないか**とあわせて1か所に並べる。

- 対象は主に A（パイロット導入）。協力校の高校生 50名、収集専用モード（[protocol](../pilot/protocol.md) §6）。B（収集専用モードを解除したサービス導入）にだけ当てはまる行には【B】を付ける。区分は [feature-inventory](feature-inventory.md) の「前提: 2つの導入」に合わせた。
- 研究期間は **28日・区分なし**として書く（#315）。`main` の [protocol](../pilot/protocol.md) と [feature-inventory](feature-inventory.md) はまだ「50名×21日（14日＋7日）」と書いている。28日への変更は PR #328 にあり、未マージである。
- この文書は臨床的な安全性評価でも、法的な評価でもない。どちらも専門家の判断が要る。
- 「現在の緩和策」に挙げたものは、リポジトリにある文書とコードだけである。本番・パイロット環境の実設定は確認していない。

## 2. 評価の尺度

発生可能性と影響は、起草者の判断による3段階である。**数値の根拠を持たない。** レビューで変えてよい。

| 段階 | 発生可能性 | 影響 |
| :-- | :-- | :-- |
| 高 | 今の実装・体制で再現できる、または構造上必ず起きる | 生命・身体の危険を見逃す。未成年の個人データが権限の無い人に渡る。研究の中止に至る |
| 中 | 条件がそろえば起きる。起きる手順を説明できる | 誤った介入、生徒の不安や萎縮、教職員の負担、参加者への不利益 |
| 低 | 複数の条件が重ならないと起きない | 運用の手間、表示の誤り |

「責任者の役割」は役割名で書く。人名・連絡先は [incident-runbook](../pilot/incident-runbook.md) §1 の非公開台帳で管理するもので、ここには書かない。同表は現在すべて `DECISION REQUIRED` である。

## 4. 緩和策が「なし」の項目

表の中で、既存の文書・コードに緩和策が見つからなかったものを集める。**ここが導入前に埋めるべき穴である。**

1. 否定・引用・誇張による偽陽性を抑える仕組み（R5）。Issue も無い。
2. 伏せ字・俗語・婉曲表現の検知（R1）。#388 の範囲外で、Issue も無い。
3. 教職員側の受け口の手順と、教職員向けの研修・同意記録（R6、R11）。
4. 語彙判定が何を拾わないかを教職員に説明する文書（R11）。
5. 自動の危機通知と runbook の関係の整理（R15）。
6. 連絡体制そのもの（R13）。runbook §1 が未記入。

夜間・休日の空白（R2）は、緩和策が無いのではなく、**設計として受け入れて説明する**ものである。説明が説明文書に正しく載ることが緩和策になる。

## 5. 見直しの条件

次のどれかが起きたら、この文書を見直す。

- #397 / #399 がマージされた（R1・R5 の数字が変わる。[safety_corpus](../../sentra/shared/safety_corpus/README.md) の `baseline.json` も更新する）
- 合成コーパスの期待判定に、臨床側のレビューが入った（R1・R5・R12）
- PR #328 がマージされた（R18、§1 の期間の書き方）
- runbook §1 の連絡体制が埋まった、または dry run（#168）を実施した（R13・R14）
- 募集を始める前（`pilot_studies.status` を `recruiting` にする前）
- 収集専用モードを解除する前（【B】の行、とくに R3・R19）
