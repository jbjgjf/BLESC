## 全チーム共通：このブロックと担当ブロックを渡す

```text
あなたはBLESC研究エンジンの担当チームです。担当Issueの成果と受け入れ条件まで実装してください。
この会話を知らない前提で、Wiki Research-Engine、全体設計、数学入門、モデルの数学、受け渡し仕様、評価仕様、72時間計画、担当Issueを読んでください。
リポジトリのCONTRIBUTING.mdと適用されるAGENTS.mdを読み、最新mainと既存PRを確認してください。文書の予定パスを実装済みと誤認しないでください。
目的は、合成観測→学習表現→履歴を使う予測→学習する説明グラフ→独立評価をつなぐことです。3日間で人の全精神状態や因果を解明したとは主張しません。
独立したbranch/worktreeを用意し、担当チームの所有範囲で変更してください。共有schema/依存/CI/API登録の変更はT0へ提案します。PR #138の保存・同意経路を同時に編集しません。
入力と出力はresearch-plan-v1の契約に合わせます。依存実装がまだない場合は版付きfixtureで開発を進め、最後に本物の出力へ差し替えます。
未学習の重み、固定された数値、ランダムな出力を成功として扱わないでください。未対応、データ不足、失敗は型で返します。機能フラグを正直に記録します。
観測とモデルの候補、モデル内操作と現実の因果、bootstrap頻度と事後確率、合成評価と実参加者評価を区別してください。
raw journal、参加者識別情報、認証情報をGitHubへ書かないでください。初回は合成データだけを扱い、API/クラウド費用が必要な拡張はT0へ実測可能な計画を渡します。
各式について「変数・単位・仮定・目的・実装箇所・破綻条件」を短く説明してください。高校数学を超える語は数学解説へリンクし、未掲載なら説明案を添えます。
PRを小さく分け、担当Issue、動作例、意味のあるテスト、再現コマンド、AI使用、残る制約を記載してください。自分だけでレビュー完了にしません。
最後にcommit SHA、契約版、artifactの場所、実際に実行した検証、未完了事項をIssueへ残してください。コマンドを実行していない場合はその旨を書いてください。
```

## T0：統括・契約・統合

```text
担当はT0aとT0bです。目的は6チームの出力が同じ契約で接続されることです。
最初の6時間でC1〜C6を実行可能な型/schemaにし、valid/invalid fixtureを共有してください。潜在次元、horizon、時刻単位、normalizer、status、artifact IDを固定します。
所有範囲はresearch_engine/contracts、cli.py、configs、共有依存、FastAPI接続、CIです。他チームのモデルを代わりに書き換えないでください。
ネットワーク不要のsmokeを作り、合成データから実際の小型学習、checkpoint再読込、予測、説明、評価JSONまでつなぎます。API骨格を先に出し、最終統合PRを別にします。
研究者権限、runの対象範囲、入力の許可、idempotency、失敗状態を境界で検証してください。既存の同意や学習ゲートを弱めません。
受け入れ：契約の拒否例が通る／fresh checkoutでsmoke完走／実reportがUIへ届き、CI・レビュー・証跡が揃う。
H24/H48で統合を実演し、H36以降の破壊的変更を止めてください。未完了の機能は能力フラグと次段階Issueへ記録します。
```

## T1：観測・データ契約

```text
担当はT1aとT1b、所有範囲はresearch_engine/dataです。
temporalの観測・出典・同一性を読むアダプターを作り、C1へ変換してください。元の観測ログを変更しません。
出来事時刻、記録時刻、利用可能時刻を分け、未知の時刻を推測で埋めません。観測されない値はnull/mask、ゼロの実測値とは区別します。
T5の分割規約に従うmanifestを作り、同じ人・元軌道・言い換え家族の漏洩を防いでください。正規化はtrainだけでfitし、normalizer_idを保存します。
Day 3はsyntheticのみを許可し、実データには明示的なunsupported/拒否を返してください。既存PR #138をマージ済みと仮定しません。
受け入れ：入力順と再取込に頑健／未来・schema違反を拒否／train-only正規化と分割検査が再現する。
T2/T3/T5へmanifest、fixture、読取例、欠測の意味を渡してください。生成器の真の潜在状態は学習特徴へ混ぜません。
```

## T2：学習する表現

```text
担当はT2aとT2b、所有範囲はresearch_engine/representationです。
C1を入力し、C2のEncodedSequenceを返す小型の予測encoderを実装してください。Day 3は合成の数値観測を使い、外部APIなしで本当に重みを更新します。
過去から将来の観測/表現を予測する目標を用意し、constant representationへの崩壊を検査します。使用する目標側の更新法と正則化を説明してください。
真の潜在状態やheldoutを教師に混ぜず、各時点でavailable_atまでの履歴だけをencodeします。JEPA論文を完全再現していなければ別のmodel_kindにします。
fit、encode、save/loadを用意し、artifactにschema、normalizer、設定、seed、データhashを含めてください。ロード後の出力を比較します。
受け入れ：更新が生じた学習ログとcheckpoint／漏洩と崩壊を検出する試験／未学習・不一致を拒否する再読込試験。
T3/T4へ凍結したencoder版と実際のEncodedSequenceを渡してください。潜在軸を未検証の感情名に置き換えません。
```

## T3：動的モデル・予測

```text
担当はT3aとT3b、所有範囲はresearch_engine/dynamicsです。
持続値と線形の比較モデルを先に作り、全モデルが同じC3を返すようにしてください。その後、凍結したT2 encoderを使う履歴モデルを学習します。
delta_daysとmaskを入力に含め、同じ現在値でも異なる過去で予測が異なりうるようにしてください。Day 3に連続時間SDEが未実装なら離散モデルと明記します。
forecastとモデル内rolloutの境界を分けます。未対応の操作は拒否し、現実の介入効果を主張しません。推論時に未来を読みません。
確率モデルを実装する場合は分布の種類と尺度を定義してください。不確実性が未実装ならnullと能力フラグfalseを返します。
受け入れ：全baselineと学習モデルを同じheldoutで比較可能／記憶の合成ペアに応答／保存・再読込・不規則時刻・不足データを検証。
T4へ凍結モデル、操作の定義、paired rollout例を、T5へ予測台帳の素材を渡してください。
```

## T4：説明・抽象化・高次構造

```text
担当はT4aとT4b、所有範囲はresearch_engine/abstractionです。
凍結したT3のモデルからz=tau(h)と説明モデルgを学習し、C4を出してください。説明文をLLMで生成するだけでは完成になりません。
詳細モデル→射影と、射影→説明モデルの二経路を比較します。constant tauでも合格しないよう、zからの予測や合成の既知アンカーとの対応も検証してください。
最初は加算型と一つの積項を比較し、candidate hyperedgeのsource_idsと相互作用次数を出します。測定の座標と単位を固定してください。
平均の一致誤差と分布の忠実度を混同しません。Wassersteinを実装していなければその名前を付けません。seed/再標本化のばらつきは真の事後確率とは別ラベルにします。
受け入れ：学習された射影とg／記憶・積項を外した比較／根拠、仮定、残差、不確実性種別を含むC4。
既存のcandidate層との境界を守り、観測やcuratedを書き換えません。出典のない候補に文献根拠を自動付与しません。
```

## T5：独立評価・反証

```text
担当はT5aとT5b、所有範囲はresearch_engine/evaluationと独立した合成fixtureです。
評価仕様のS1〜S5を用意し、H6までに生成器、分割、seed、比較、測定値と解釈を固定してください。真の潜在状態と構造は学習側へ渡しません。
T1には観測と分割規約を渡します。T2〜T4の出力に対し同じtarget・単位・splitで比較し、悪化や未対応もC5へ出します。
最低3seedの実測値、予測誤差、区間の被覆率/幅、説明忠実度、合成構造回復、計算量を報告してください。該当しない指標はnullと理由にします。
未来の一行を入れる、未学習重みを使う、schemaを入れ替える等の故障を注入し、評価が拒否できることを確かめてください。
予測台帳はcutoff、発行時刻、model/input/output hashを持ち、historical_simulationとprospectiveを分けます。hashだけで改ざん不能とは説明しません。
受け入れ：漏洩検査と反例が失敗を捕捉／実baselineと新モデルの同一report／再実行コマンド、利用量、限界が揃う。
モデル作者が最終テストを見てから条件を変更した場合は新しい実験版にし、既存結果を消さないでください。
```

## T6：研究画面・理解可能な表示

```text
担当はT6aとT6b、所有範囲は研究world-modelページと専用componentです。frontendのAGENTSとローカルNext.js文書を先に読んでください。
版付きC3/C4/C5 fixtureで画面を作り、最終的にT0のAPIが返す本当の実行結果へ接続します。参加者向け日記、同意、チャットを改変しません。
観測の時系列と予測区間、モデル候補グラフ、根拠参照、残差、仮定、run/model/splitの版を表示してください。観測・候補・文献は視覚上も区別します。
loading、empty、not_enough_data、unsupported、failed、forbiddenを作ります。demo/fixtureラベルを実結果に残さず、逆にfixtureを実結果と偽りません。
説明には「モデル内の推定」を明記し、未検証の軸を病名として表示しません。専門語には短い日本語説明と数学Wikiへのリンクを付けます。
受け入れ：主要状態のブラウザ証跡／APIの新しいrunで表示が更新／無権限・部分未対応・出典なしを適切に表示。
T5のreportを直接根拠にし、成功率や参加者数を固定値で描画しないでください。
```
