# R2: 多時間尺度・高次構造・部分識別の比較実験

> 研究計画。実験の実行ではない。#154 / 依存 #150 / 版 `research-plan-v1`
> v0（PR #169）が固定した3つの単純化を、どの順で外すかを設計する。

## 1. v0が置いた単純化と、その代償

| v0の単純化 | 実装上の現れ | 外さないと起きること |
| --- | --- | --- |
| 離散時刻・1日1歩 | encoderは `log1p(経過日数)` を入力に取るが、遷移自体は1歩ずつ | 3日空いた区間を1歩で埋め、変化の速さを取り違える |
| 遅れは1日固定 | 説明モデル `g` はlag=1の項だけ | 数日遅れて効く関係が、係数0か直近の項に吸収される |
| 相互作用は2次まで | 積項は `x_i · x_j` まで | 3者の組合せでのみ現れる効果を探索しない |
| 構造は点推定 | 閾値で切ってbootstrap選択割合を添える | 「辺があるか」の不確かさを分布として持たない |
| 識別可能性を問わない | 候補辺を全部出す | S5のように未観測共通要因があると偽陽性が出る（実測 precision 0.13） |

最後の行はv0の実測値である。S5でedge precisionが0.13だったのは実装の不具合ではなく、**lag-1の辺で観測変数間の依存を説明しようとすれば当然そうなる**という事実の表示である。R2はここを正面から扱う。

## 2. 外す順序

いっぺんに外すと、改善がどれによるものか分からなくなる。**1つずつ、同じ評価条件で**外す。

```
v0 (baseline)
 ├─ E1 連続時間の遷移              → 不規則な間隔が正しく扱えるか
 ├─ E2 複数の遅れ（lag 1..K）      → 遅れて効く関係を拾えるか
 ├─ E3 3次以上の相互作用           → 組合せ効果を拾えるか / 偽陽性が増えないか
 ├─ E4 構造の事後分布              → 「辺があるか」を分布で持てるか
 └─ E5 部分識別                    → 因果として言えることの範囲を限定できるか
```

E1〜E3は予測成績と構造回復の両方で採点する。E4とE5は予測を改善しないことがあり、それでも価値がある——**主張を弱める**ことが成果になる段階だからである。

## 3. 各実験

### E1 連続時間

**仮説**: 不規則な観測間隔では、経過時間を状態遷移に明示的に入れたモデルが、間隔を入力チャネルとしてのみ扱うv0を上回る。

**方法**: 遷移を `h(t+Δ) = F(h(t), Δ)` の形にする。最小構成は、状態の減衰を `exp(-Δ/τ)` で書く連続時間の線形部分と、観測時に効く更新項の組合せ（線形SDEの離散解、またはneural CDEの縮約）。v0のGRUは比較対象として残す。

**新しい合成シナリオ**:

| ID | 機構 | 暴きたい失敗 |
| --- | --- | --- |
| S7 | 速い成分（時定数1日）と遅い成分（時定数10日）の和。観測間隔をランダムに1〜5日 | 1歩=1日の遷移が速い成分を潰す |
| S8 | 観測間隔が状態に依存（悪い日ほど間隔が長い） | 欠測をランダムと仮定して偏る |

S8はR1の4.2で「欠測が予測できてしまう」場合に必要になる。**実データの欠測が系統的だと分かってから作るのでは遅いので、先に作る。**

**採点**: 既存のMAE/RMSE、および「観測間隔が長い区間だけを取り出したMAE」。全体平均では間隔の短い区間に埋もれる。

### E2 複数の遅れ

**仮説**: 真の遅れが1日でないとき、lag 1..K を探索するモデルが lag=1 固定のv0を上回り、かつ真の遅れを回復する。

**方法**: 説明モデルの設計行列を lag 1..K（K=5程度）に拡張。項が増えるので、選択は群Lasso（同じ元→先の全lagを1群として出し入れ）にする。単純に閾値を上げるだけだと、弱く広がった遅れが全部落ちる。

**新しい合成シナリオ**: S9 — 真の遅れが 2日と4日の混合。lag=1だけを持つモデルはこれを直近の項に押し込む。

**採点**: 辺のprecision/recall（元・先・遅れの3つ組で一致を判定）に加え、**遅れの推定誤差**（真の遅れとの日数差）。

**注意**: v0のS2は5日移動平均への依存で、`structure_defined=false` として構造回復を算出していない。E2でlagを増やしても、移動平均は単一lagの和では厳密には表せない。**S2の構造回復を「算出できる」に変えるのは、移動平均を表せる形（分布lag／基底展開）を入れたときだけ**にする。表現できないまま採点を始めると、低いスコアが「モデルが悪い」に見える。

### E3 3次以上の相互作用

**仮説**: 3者の組合せでのみ現れる効果があるとき、2次までのモデルはそれを検出できず、3次項を含むモデルが上回る。

**方法**: 項の数が組合せ的に増える（4変数・3次で追加14項、10変数なら120項超）ため、全探索はしない。2段階にする。(1) 2次までで残差を計算、(2) 残差に対して3次候補を選抜。選抜には安定性選択（bootstrapで一定割合以上選ばれた項のみ残す）を使う。

**新しい合成シナリオ**: S10 — `x4` が `x1·x2·x3` にのみ依存し、2次の周辺化ではほぼ見えない機構。

**採点**: S10でのrecall、および**S1〜S5でのfalse positive率**。3次を許した結果、積項のない場面で偽の3次辺が増えていないかを必ず併記する。増えているなら、それはE3の成果ではなく代償である。

### E4 構造の事後分布

**仮説**: 辺の有無を分布として持つと、点推定＋bootstrap割合よりも、真の構造の不確かさをよく表す。

**方法**: 係数にスパース事前分布（horseshoe等）を置き、事後を近似する。v0の `uncertainty_method="bootstrap_frequency"` は、`posterior_inclusion_probability` という**別の名前**で並置する。片方をもう片方に読み替えない。

**採点**: 較正。真の辺の事後確率が0.8と出た辺のうち、実際に真である割合が0.8に近いか。ここで初めて「確率」という語を使ってよい。

**契約の変更**: `CandidateEdge.uncertainty_method` に値が増える。C4のversionを上げ、fixture差分を契約Issueに出す（`Research-Contracts` の変更手順）。**既存のbootstrap割合を黙って事後確率に読み替える変更はしない。**

### E5 部分識別

**仮説**: 未観測共通要因があるとき、「効果の点推定」ではなく「効果が入りうる区間」を返すほうが、S5のような設定で誤りが少ない。

**方法**: 感度分析を先に入れる。未観測交絡の強さを1つのパラメータで置き、そのパラメータを動かしたときに符号が反転する境界（E-valueに相当する量）を報告する。次に、道具変数や負の対照が使える場合に限って区間を出す。

**採点**: S5で、v0が出した偽の `x1 → x2` 辺が「区間が0を含む」として報告されるか。**precisionが0.13から上がることではなく、0.13の中身が「断定」から「不確定」に変わることが成果である。**

**表示への影響**: 区間が0を含む辺は、画面で断定的な矢印として描かない。`evidence_scope` は `model_candidate` のままで、加えて識別状態（`identified` / `partially_identified` / `not_identified`）を持たせる。これもC4の変更である。

## 4. 共通の評価条件

**変えないもの**（実験間で比較するため）:

- 分割規約（参加者単位・時間分割の2本立て、split_groupの扱い）
- seed（最低3、全seedの値を保存）
- 目標変数と単位
- 比較対象（persistence / train_mean / linear_ar / v0のmemory_gru を常に併記）
- 参加者単位の集計と参加者bootstrap区間

**必ず併記するもの**:

- 計算量（学習時間、メモリ、推論時間）。E3とE4は明確に重くなる。予測が同点で計算量が10倍なら、それは改善ではない。
- 予測成績と説明忠実度が相反した場合の**両方**。片方だけを載せない。

**変えてはいけない運用**:

- heldoutは最終採点にのみ使う。E1〜E5の設定選択はvalidationで行う。
- 成績を見てからシナリオのパラメータを易しくしない。新しいシナリオ（S7〜S10）の母数は、最初の実験を回す前に固定して記録する。

## 5. 期待される結果と、期待していないもの

**期待できる**: E1とE2は素直に効くはずである。実データの観測間隔は不規則で、心理的な出来事の影響は当日で終わらない。

**期待していない**: E3が予測を改善すること。3次の効果が実データで検出できる規模ではない（R1の見積で有効遷移が500〜600対）。E3は**合成データで方法を用意しておく**段階であり、実データで3次辺を主張する段階ではない。

**改善しないことが成果になる**: E4とE5。区間が広く出て「言えることが少ない」と分かるのは、狭い点推定を出すより正しい。

## 6. しないこと

- 名前の一致を完成条件にしない。連続時間・ハイパーグラフ・事後分布といった語は、比較条件と選択理由がある場合にのみ使う。
- E1〜E5をまとめて1つのPRにしない。どれが効いたか分からなくなる。
- 実データでE3〜E5を先に走らせない。合成で挙動が分かってから。
- 部分識別の区間を、UIで点推定に丸めない。丸めた瞬間にE5の成果は消える。
