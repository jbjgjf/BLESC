# R3: 情報利得による観測選択と、前向き評価

> 研究計画。実験の実行ではない。#155 / 依存 #150 / 版 `research-plan-v1`
> v0では `active_questioning` は false に固定されており、configからも true にできない。この文書はそれを外すために何が要るかを書く。

## 1. なぜ最後なのか

適応的な質問は、この研究計画のなかで**唯一、参加者の体験そのものを変える**機能である。

- 予測も説明も、参加者から見れば何も起きない。外れても参加者の一日は変わらない。
- 質問選択は違う。何を聞かれたかが、その人の注意と回答を変える。**測定が介入になる。**

だから順序が決まる。(1) 固定の測定で何が測れるかを知る（R1）、(2) モデルが何を推定できるかを知る（R2）、(3) そのうえで、質問を変えることの効果と害を、固定測定の対照つきで確かめる（R3）。順序を入れ替えると、baselineが質問によって動いたあとのデータしか残らない。

## 2. 何を選ぶのか

「情報利得で観測を選ぶ」には少なくとも3つの別のものが含まれる。混ぜない。

| 対象 | 具体 | 参加者への影響 |
| --- | --- | --- |
| A. 提示順の選択 | 固定項目の順番だけを変える | 小。順序効果はあるが項目は同じ |
| B. 追加項目の選択 | 固定項目に加えて、その日だけ1問足す | 中。負担が増え、注意が向く |
| C. 内容の生成 | モデルが文面を作って聞く | 大。未評価の生成物が未成年者に届く |

**Cはこの段階の対象外にする。** 未成年者に対する生成応答の停止は収集専用モード（#165）の要件であり、R3はそれを緩める根拠を持たない。R3が扱うのはAとB、それも上限を決めたうえでのBまでである。

## 3. 情報利得の定義

「情報利得」は目的によって別の量になる。先に固定する。

| 目的 | 量 | 注意 |
| --- | --- | --- |
| パラメータの推定精度 | 事後分散の期待減少（Bayesian D-最適に相当） | R2のE4がないと事後がない |
| 次の観測の予測精度 | 予測分布の期待対数尤度改善 | 予測に効く質問と、構造推定に効く質問は一致しない |
| 構造の識別 | 辺の事後包含確率のエントロピー減少 | R2のE4/E5が前提 |

**R3はR2に依存する。** 事後分布のないモデルで「情報利得」を計算すると、実質は残差の大きい項目を選ぶヒューリスティックになる。それ自体は悪くないが、そう名乗るべきである。

## 4. 実験計画

### 4.1 まず合成で

実参加者に出す前に、合成上で選択方策を採点する。

**新しいシナリオ**: S11 — 4項目のうち、その日の状態によって「聞くと最も情報が増える項目」が変わる機構。ランダム選択・固定選択・情報利得選択を比較する。

**採点**: 同じ回答数の予算のもとで、(a) パラメータ推定誤差、(b) 次時点の予測誤差、(c) 構造回復。**予算を揃えるのが要点**で、多く聞けば良くなるのは当たり前である。

**期待される落とし穴**: 情報利得選択が「常に同じ項目を選ぶ」に縮退すること。縮退したら、それは方策の失敗であり、多様性の制約（各項目の最低頻度）が要る。

### 4.2 質問提示自体の効果を測る

適応質問の実証は、**質問提示そのものの作用**と分けなければならない。設計は3群。

| 群 | 受けるもの |
| --- | --- |
| 対照 | 固定項目のみ（R1と同じ） |
| 追加固定 | 固定項目 + 毎日同じ追加1問 |
| 適応 | 固定項目 + 情報利得で選ばれた追加1問 |

「追加固定」群がないと、適応の効果と「1問増えたこと」の効果が分離できない。負担・脱落・回答の質はどれも1問増えるだけで動く。

**主要評価**: 適応群と追加固定群の間の、予測誤差の差。対照群との比較は「1問増やすことの効果」であって、適応の効果ではない。

**安全側の評価（主要と同格で扱う）**:

- 脱落率と提出率の群間差
- 回答所要時間と、回答の粗雑さ（同一値連打、極端値の増加）
- 参加者の負担感（protocolで固定した1項目）
- 危機的記述の出現率（増えるなら即停止条件）

**停止条件**: 適応群の脱落率が対照群を有意に上回った時点で適応を止める。予測が改善していても止める。**質問が良くなることと、参加が続くことは別の目的で、後者が優先する。**

### 4.3 前向き評価

ここが唯一「予測」と呼べる評価になる。

- 予測は**回答が存在しない時点で発行**し、v0の台帳（`evaluation/ledger.py`）へ `evaluation_mode="prospective"` で追記する。
- 台帳の保存先は、参加者データを書ける権限とは**別の権限**にする。予測を書く側が結果を書き換えられない構成にしないと、封印は形だけになる。
- v0の `limitations` が言うとおり、hashは内容の一致確認であって改ざん不能の保証ではない。前向き評価では**追記権限そのものを検証**する（誰が書けるか、後から書き換えられるか）を、dry runの項目に足す。

**historical_simulation と prospective を混ぜて集計しない。** 型はすでに分けてあり、レポートも分けて出す。

## 5. 外す条件（`active_questioning` を true にできるとき）

すべて満たすまでfalseのままにする。

1. R2のE4（構造の事後分布）が動いており、情報利得が定義された量として計算できる。
2. 合成S11で、予算を揃えた比較で情報利得選択がランダム選択を上回っている。
3. 追加質問の上限（1日1問）と、質問の集合が**事前に固定**されている。生成ではなく選択である。
4. 3群設計と停止条件が研究計画に書かれ、承認されている。
5. 参加者・保護者への説明に「質問が日によって変わること」と「その理由」が書かれ、同意のversionに含まれている。
6. 台帳の追記権限分離が実装され、dry runで検証されている。

これらは `CapabilityFlags` の `active_questioning` を true にするPRのチェックリストとしてそのまま使う。v0の `FORBIDDEN_IN_V0` からこのフラグを外す変更には、上の6行への証跡を添える。

## 6. しないこと

- 参加者向けの画面で、選ばれた質問の理由をモデルの推定として表示しない。「あなたは今日〜のようなので」は、未検証の推定を本人に返す行為である。
- 情報利得を「その人にとって重要な質問」と言い換えない。情報が増えるのはモデルにとってであって、本人にとってではない。
- 適応質問を、支援や介入として説明しない。R3は測定設計の実験であり、効果があるという主張ではない。
- 予測が改善したことを理由に、安全側の指標が悪化したまま続けない。
