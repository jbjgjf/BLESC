# デモ導線とリリースゲート

#17。デモを通すための手順と、出す前に確認することをまとめています。

## 前提

**ログインも API キーも Supabase も要りません。** 固定データで全画面が動きます。

```bash
cd sentra/frontend
npm install
npm run dev
```

ブラウザで **http://localhost:3000/demo** を開きます。`next dev` はデモモードが
既定で有効なので、設定は不要です。

- バックエンド（FastAPI）は起動しなくて構いません。デモは触りません。
- `.env.local` も不要です。無くても起動します（本番ビルドでは従来どおり、
  資格情報が無ければ起動時に失敗します）。
- デプロイ先でデモを見せたいときだけ `NEXT_PUBLIC_DEMO_MODE=1` を設定します。
- 1つのタブだけデモにしたいときは URL に `?demo=1`、戻すときは `?demo=0`。

## 5分の導線

`/demo` に同じものが画面上に出ます。読み上げ用に、ここでは意図も併記します。

| # | 画面 | 見せること | 言うこと |
| :-- | :--- | :--- | :--- |
| 1 | `/` → `/journal` | 今日の記録。1画面1問で書ける | 「入力の負担を増やさないことが最初の条件です」 |
| 2 | `/reflect` | 21日分の気分の推移と、よく出る話題 | 「1日の出来事ではなく、繰り返しを見ています」 |
| 3 | `/educator/roster` | 教員が受け取る観測 | 「出るのは観測された記述と時刻だけです。リスクの判定は出しません」 |
| 4 | `/support-summary` → `/oversight` | サマリーを作り、共有先を選ぶ → 担当者側に届く | 「共有するかは生徒が決めます。日記の本文は送られません」 |
| 5 | `/audit` | AI処理の履歴 | 「何がいつ動いたかを本人が確認できます。残るのはハッシュです」 |

余裕があれば `/chat` で「消えてしまいたい」と入力してください。決定的な安全判定が
働き、人につなぐ応答に切り替わります。**このぶんはモデルに接続しません** — 提供元が
落ちていてもこの挙動は見せられます。

## 収録するときの確認

- [ ] ブラウザは新しいプロファイル（ブックマークバー、拡張機能、通知を出さない）
- [ ] 画面右下に「デモデータ」の表示が出ていることを画に入れる
- [ ] `?demo=1` を付けたまま開始し、URL バーを隠さない
- [ ] 共有の状態はタブを閉じると消える。撮り直す前に一度タブを閉じる
- [ ] 音声は使わない（デモでは動きません）
- [ ] 収録後に見返して、実在しそうな氏名・学校名が固定データのものだけであることを確認する

## このデモで見えないこと

正直に言えるようにしておくためのリストです。

- **音声入力と音声モードは動きません。** マイクと OpenAI Realtime への接続が要ります。
- **AI の応答は固定文です。** 実際の応答はモデルが生成します。デモで固定にしているのは、
  提供元が落ちていてもデモが止まらないようにするためです。`status` は `demo_fixture` を返します。
- **最初の14日間に「変化の大きさ」が出ないのは不具合ではありません。** 本人の記録が
  14日分たまるまで比較しません（`RAMP_UP_DAYS`）。デモの生徒は21日目なので、
  ゲートが外れる前と後の両方が見られます。
- **共有の状態はタブの寿命です。** `sessionStorage` に置いているので、閉じると
  「何も共有していない」状態に戻ります。サーバーには何も送りません。
- **教員の閲覧記録は書き込みません。** デモには書き込む先がないためです。生徒側の
  「だれが見たか」に出るのは固定データです。
- **実データでの検証ではありません。** 出てくる生徒はすべて固定データで、
  実在しません。精度・臨床的妥当性については何も示していません。

## リリースゲート

出す前に、この順で確認します。

### 自動で確認できること

```bash
cd sentra/frontend
npm run lint          # クリーン
npm test              # 日本語UIの検査を含む
npm run build         # 本番ビルド

cd ../backend
python -m pytest tests -q
```

- [ ] 上の4つがすべて通る（CI の `Research Contracts` と同じ内容）
- [ ] `npm test` の「Japanese UI」が通っている = 画面に英語が残っていない
- [ ] 資格情報なしの `npm run build` が**失敗する**こと。起動時に落ちない設定ミスは、
      1画面ずつ壊れて出ていくより悪い

### 人が見て確認すること

- [ ] `/demo` の5ステップを、資格情報なしのクリーンなクローンで通せる
- [ ] 各画面に読み込み中・空・エラーの表示がある（デモモードで一度確認する）
- [ ] 教員側の画面に、根拠のない観測が出ていない
- [ ] 教員側の画面に、リスクの帯（3段階の分類）が復活していない
- [ ] スクリーンショットに実在しそうな個人情報が写っていない
- [ ] 安全に関する導線（`/chat` の危機表現、`/educator/alerts` の手順）が
      モデル接続なしで動く
- [ ] 日本語として不自然な箇所がない（`docs/localization/style_guide.md`）

### 出したあと

- [ ] 本番の `/api/health` で、必要な設定がそろっていることを確認する
- [ ] AI チャットを1往復ためす（OpenAI の残高切れは無言で定型文になるため、
      画面を見ただけでは分からない）

## 仕組み

デモの固定データは2か所にあります。

- `src/lib/blesc/fixtures.ts` — このアプリ自身の語彙（日記、名簿、面談記録）。
  画面が直接読みます。
- `src/lib/blesc/demoApi.ts` — API が返す形。`ApiClient` がデモモードのとき
  これを返します。日記を1つ変えると、グラフも、タイムラインも、監査記録も、
  教員に見えるものも一緒に動きます。

どのメソッドがデモに対応しているかは `grep readDemoFlag src/api/client.ts` で
一覧できます。対応していないものは、デモでも従来どおりエラーを出します。
