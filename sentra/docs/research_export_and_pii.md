# 研究データの取り出しと PII レビュー

対象 Issue: #167。関連: #131（原文の保管）、#134（同意）、#164（参加登録）。

## 1. 出力は2つあり、権限が別になっている

| 出力 | 経路 | 許可 | 中身 |
|---|---|---|---|
| 研究データセット | `GET /api/research/export` | `RESEARCH_EXPORT_USER_IDS` | 仮名（`research_code`）、相対日、尺度、オントロジー、provenance、暗号化原文への管理参照 |
| 身元対応表 | `GET /api/research/identity-map` | `RESEARCH_IDENTITY_MAP_USER_IDS` | `research_code` ↔ `participant_id`、コホート、状態、開始日、撤回日 |

**両方を同じ人に渡すと分離は無くなります。** 変数を分けてあるのはそのためで、
同じ id を両方に書けば設計上の分離は消えます。意図してそうするとき以外は分けてください。
どちらも空なら誰も実行できません（ロールではなく明示列挙なのは、
「いつのまにかその権限に入っていた」を起こさないためです）。

両方とも、成功・拒否・失敗のすべてが `research_exports` に記録されます。
`export_kind` が `identity_map` の行を数えれば、「誰がいつ仮名を解いたか」だけを
データ取り出しと切り離して追えます。

### データセットに入らないもの

- `participant_id` / `owner_user_id` / メールアドレス（ログインIDへ直接辿れない）
- 絶対時刻。日付は「その参加者の観測開始日から数えた相対日」だけです。
  実時刻を復元するには対応表側の `collection_started_at` が要ります。
- `evidence_text`。オントロジーのノードは根拠となった文を原文のまま引用しますが、
  原文の保管に同意していない参加者については、これを除去してから出します。

  これは細かい改良ではなく、この分離の主目的です。以前の export は `raw_text` だけを
  同意で絞り、`extraction_json` はそのまま出していたため、
  **原文保管に同意していない参加者の日記本文が、断片として出ていました。**

- 撤回した参加者の行。撤回は同意とは別の状態（`pilot_enrollments.state = 'withdrawn'`
  または `withdrawn_at` が入っている）で、**同意より先に判定します。**
  撤回と同意撤回は別々に書き込まれるため一瞬食い違うことがあり、
  そのとき「同意が無い」ではなく「撤回した」と数えないと、除外理由の集計が嘘になります。

対応表のほうは撤回者も**含みます**。撤回を実行する（該当行を見つけ、原文を消し、
本人に完了を伝える）にはその人の対応が必要だからです。

## 2. PII スキャナにできること・できないこと

`src/lib/piiScanner.ts`。**これは匿名化ではなく、人が読むための優先順位付けです。**

### 見つけられるもの

| 種類 | 確度 |
|---|---|
| メールアドレス、電話番号、郵便番号、URL、SNSハンドル | high |
| 学校名、氏名+敬称、住所 | medium |
| クラス・出席番号、生年月日らしき日付 | low |

### 原理的に見つけられないもの

ここが一番大事です。

- **ひらがなの下の名前。** 「ゆいちゃんとけんかした」の「ゆい」は名前でもあり、
  ただの語の断片でもあります。パターンでは切り分けられません。
- **名前を出さない特定。** 「クラスで唯一オーボエを吹いている子」には名前がありませんが、
  50人のコホートでは一人に絞れます。
- **関係による特定。** 「うちのお母さんの職場」。

**したがって、findings が 0 件であることは「PII が無い」ことの証明にはなりません。**
`scanForPii` が「安全だから出してよい」と判断することはありませんし、
`redactFindings` は表示とログのための伏字であって、匿名化処理ではありません。
伏字をかけた本文も、依然として参加者の本文です。

### レビューの運用

1. `include_raw_text=1` で取り出した行には `pii` が付きます（`high`/`medium`/`low` の件数と findings）。
2. `high` が付いた行から人が読みます。`high` は「連絡先が書かれている」に近く、確度が高い順です。
3. `low` しか無い行、findings が 0 件の行も、**抽出精度の評価に使う分については人が読みます。**
   上に書いたとおり、0 件は無いことの証明ではないからです。
4. 見つかった PII は、原文を消すか、当該行を評価対象から外すかを決めて記録します。

## 4. 設定

```
RESEARCH_EXPORT_USER_IDS=          # データセットを取り出せる auth.users.id
RESEARCH_IDENTITY_MAP_USER_IDS=    # 仮名を解ける auth.users.id（上とは別の人にする）
RESEARCH_RAW_TEXT_KEY=             # 32バイト base64。未設定なら原文は保管されない
RESEARCH_RAW_TEXT_RETENTION_DAYS=  # 既定 180
PILOT_TIMEZONE=Asia/Tokyo          # 相対日の境界を決める
```

`purge_expired_raw_text()` の定期実行は別途割り当てが必要です。
EXECUTE は `service_role` のみに絞ってあるので、cron はその権限で回してください。
