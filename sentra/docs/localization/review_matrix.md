# 翻訳レビューマトリックス

各画面の文言と、その日本語のレビュー状況です。

`sentra/frontend` の全画面を機械的に走査して作成しました（`npm test` の
「Japanese UI」テストが同じ走査を実行しています）。走査対象は `src` 配下の
`.tsx` / `.ts` で、除外したモジュールは `scripts/ui-strings.mjs` の
`MACHINE_MODULES` に理由つきで記載しています。

## ステータス定義
- `未` : 未着手（英語のまま、または抽出のみ）
- `初稿` : 一次翻訳完了
- `文脈` : 画面に当てはめて文脈確認済み（実機での目視は未実施）
- `完了` : 実機で確認し、スタイルガイド準拠を確認済み

## 実機確認の方法

`scripts/ui-display-qa.mjs` が全画面をデスクトップ（1280×900）とモバイル
（390×844）で開き、次を実測します。ビルド済みのアプリを起動してから実行します。

```bash
node scripts/ui-display-qa.mjs --base-url http://localhost:3000
```

| 検出するもの | なぜ |
| :--- | :--- |
| 横スクロールの発生 | 日本語の方が長くなる行があり、モバイルで画面外へ出る |
| 文字切れ（clip / ellipsis） | ボタン幅や固定幅のセルに収まらない訳がある |
| 読み上げ名のない操作要素 | アイコンだけのボタンは「ボタン」としか読まれない |
| 画面に残る英語 | カタログを経由していない文言 |
| ログイン画面が代わりに出た画面 | 測っていないのに合格と記録するのを防ぐ |

全画面を `?demo=1` で開きます。付けないと未ログインではログイン画面が出るため、
24 画面を「開かずに合格」と記録することになります（実際に最初の版がそうでした）。
実データでしか出ない状態（長い自由記述、空の名簿）は、この走査では確認できません。

## 文言の置き場所

画面に出る文言はメッセージカタログ `src/lib/i18n/ja.ts` にあります。表の
「カタログ」列は、その画面の文言がカタログに移されているかを示します。移行前の
画面は日本語ではあるものの、文言がファイル内に直接書かれています。

## 残っている作業

カタログ移行は 2026-09-10 に完了しました。実機での表示確認は 2026-09-12 に
`scripts/ui-display-qa.mjs` で 24 画面 × 2 画面幅 = 48 通りを走査し、検出された
不具合を修正しました（下記）。上表の `完了` はこの走査を通ったことを指します。

残りは次の 3 つです。

- **学校関係者によるコピーレビュー**: 生徒向け・教員向けそれぞれの導線を、実際の
  学校の方に読んでいただき、指摘を反映する。これは走査では代替できません。
- **AI の応答・抽出の日本語**: プロンプトで日本語を指定してありますが、実際の
  出力は走査していません。モデルを動かして、通常応答・要約・安全配慮の定型文を
  読む必要があります。
- **`/research` の本文の切り詰め**: 続きを読む手段を付けるかどうかの判断。

### 実機確認で見つかり、修正したもの（2026-09-12）

| 画面 | 症状 | 原因 | 対応 |
| :--- | :--- | :--- | :--- |
| `/graph` | 「Layout is visual; it is not diagnostic.」が英語のまま | 走査側の欠陥。`;` を含む文字列を機械的にコードと判定していたため、この 1 文だけが検出をすり抜けていた | `t.graph.layoutNotice` へ移動。走査は、`;` のほかに括弧・等号・キーワードがある場合だけコードとみなすよう修正 |
| `/research` | 日時が `Sep 11, 09:14 PM` と英語表記 | `toLocaleDateString(undefined, …)`。ロケールを実行環境（サーバは Node の既定、ブラウザは閲覧者の設定）に委ねていた | `"ja-JP"` を明示。`counselor-summary.ts`（支援担当へ共有される文面）と `/school` の人数表記も同様に修正 |
| `/reflect` | モバイルでページ全体が横スクロールする | `MoodTrend` の日付行。flex セルの `min-width` 既定値 `auto` と `nowrap` により、21 個の日付が常に約 800px を要求していた。非表示のセルも幅を主張していた | セルに `min-width: 0`。両端のラベルだけ行の端に寄せる |

### 走査では判定しないもの

- `/research` の記録一覧は、生徒自身の日記本文を `truncate` で 1 行に切り詰めて
  います（1875px の本文に対して表示幅 528px）。日本語化で生じたものではなく、
  英語でも同じように切れる一覧の設計です。**続きを読む手段が画面上にないこと**が
  問題で、`title` を付けるか展開できるようにするかは、この issue ではなく UI の
  判断として残します。
- 装飾目的の背景 SVG と、読み上げ専用の 1px ラベルは、`overflow: hidden` の箱から
  はみ出しますが不具合ではありません。走査はこの 2 つを除外します。

### 移行で分かったこと

`/educator/alerts`・`/educator/class`・`/educator/meetings`・`/school` の 4 画面は、
企画書の固定データで動くデモ専用の画面です（`AppNav` の `DEMO_ONLY_NAV_PATHS` に
入っており、通常のナビゲーションには出ません）。移行の作業中に、この 4 画面のうち `/educator/class` が生徒ごとのリスクバンドを
描画していることが分かりました。`docs/educator_display_policy.md` の規則 1 に
反しており、**バンドの是非はローカライズの範囲外**なので #175 として起票し、
そちらで画面を観測表示に作り直しました。`educatorDemo.class` の文言も、その際に
書き直しています。

なお `educator_display_policy.md` 自身が「a policy enforced in one of two
implementations is not enforced」と書いています。これはその 2 例目でした。
