# Direct dependencies, pinned (#184).
#
# Every version here is `==`. Before this, all but two were bare names, so
# `pip install -r requirements.txt` resolved whatever was newest on the day CI
# ran — which meant a green run could go red with nothing in this repository
# changing, and a past run could not be reproduced at all.
#
# That is not a style point for this repository in particular. The research
# contracts workflow runs the engine smoke and uploads artifacts whose reports
# record the environment ("numpy 2.4.6, python 3.11.15"). Handing someone a
# number and no way to rebuild the dependency graph that produced it is not a
# reproducible result, and `scikit-learn`, `umap-learn`, `hdbscan` and
# `sentence-transformers` all change numerical behaviour across minor releases.
#
# `requirements.lock.txt` beside this file pins the transitive set as well, and
# is what CI installs. This file stays readable: it says what this project
# actually asks for, at a version somebody chose.
#
# To move a version: change it here, re-resolve, and regenerate the lock with
#   python -m pip install -r requirements.txt --dry-run --ignore-installed \
#     --report /tmp/resolve.json
#   python scripts/write_lockfile.py /tmp/resolve.json
#
# Run that on Linux, under the Python the workflow uses. The script refuses
# anything else and says why: the resolved set differs by platform and by
# interpreter, so a lock made elsewhere pins something CI never installs.
# `requirements.lock.txt` records which pair it was resolved under (#206).
